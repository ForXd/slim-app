# Slim App

Maintained product is native Android Java, package cn.qingji.diary, minimum API 28.

- Sources: android/src/cn/qingji/diary; build: sh android/build.sh (JDK 17, Android SDK 35).
- Preserve JournalStore/ChallengeStore schemas and existing signing identity for upgrades.
- Keep all keys, keystores, credentials and generated APKs out of git. Release binaries are GitHub Release assets.
- Do not auto-record inferred food; require user confirmation of candidate and portion.
- Update files must pass size, SHA256, package, version and installed signing certificate checks before installation.
- Challenge count is completed cells (maximum 100), not distinct calendar dates.
- Run FeatureCheck for challenge/update changes and DeckCheck for pager gesture changes and NativeCheck for food database/model changes on Android.
- Keep source attribution and licenses when updating models, nutrition data or test photos.
- Native version comes from android/AndroidManifest.xml. Release metadata is generated by scripts/release.sh.

- Visual language: warm paper texture, regular Noto Serif CJK headings, system sans body/controls and tabular numeric readouts, vermilion actions, botanical art, quiet outlined cards. Reference: docs/design/0.6/reference.png. Do not revert to oversized default button stacks.
- ChallengePager uses a bounded three-layer native card stack and updates the grid after settling. Verify rebound, edge stacks, parent ScrollView arbitration, animation cancellation, search, archive filtering and large font layout after changes.
- UiFixture is test-only and must run exclusively on isolated emulator data. scripts/verify-ui.py exercises the native UI.

- Run TrendCheck for trend aggregation, RevisionCheck for plan/calendar/season boundaries, and EnergyCheck for energy-state changes. Keep tests isolated from user preferences.
- Automatic themes follow calendar months; never claim exact solar-term timing. Food/energy values and plan projections remain estimates; missing records are not zero.
